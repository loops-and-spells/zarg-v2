# Feedback Implementation Plan (plan 1 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Testers' feedback lives outside rehearse, tied to the card version the tester saw, and is triaged (on/off) in a new Feedback nav view; rehearse only reports, and the old "Send to zarg" path (the findings gate) is gone.

**Architecture:** A new first-party sandboxed plugin, `@zarg/plugin-backlog` (plugin name `backlog`), stores feedback entries as committed JSON under `.zarg/feedback/`, serves them as `backlog/feedback` entities, and fills a Feedback nav view (a stepper, the journeys with open feedback, the selected journey's feedback as toggle rows, the entry in full beside them). Rehearse depends on its contract to file what its testers found, with the card's version (from `Entities.version`) and rehearse's own triage verdict as the agent's first call. The view SDK gains toggle tables (`toggle: true`, rows carry `on`; space sends `act "toggle"`).

**Tech Stack:** Bun, Effect 4, the plugin SDK (`definePlugin`, `pluginContract`, `Entities`, `Views`, `Files`), OpenTUI React.

**Spec:** `docs/superpowers/specs/2026-09-28-feedback-backlog-design.md` (sections Feedback, The triage hub stage 1, Rehearse and testers, Packages); refs and versions from `docs/superpowers/specs/2026-09-28-entities-design.md`.

## Global Constraints

- Feedback entries are one JSON file each under `.zarg/feedback/`, committed (not gitignored).
- An entry's id is `F-` plus a hash of its ref (with version), kind and normalised note: the same report on the same card version is one entry; its `count` rises and its triage stays.
- State: `open` (its ref is current), `stale` (the ref's entity changed or went), `planned`, `closed`. Only `open` entries show in Triage.
- Triage: `{ on, why, by: "agent" | "operator" }`; the operator's flip is marked and survives the agent's next pass.
- Plugins name only plugin tones; buttons in views, keys on the status line.
- Rehearse no longer triages for zarg: no `apply`, `dismiss`, `agenda`, `finding`, `resolved`; its findings leave the review queue.
- `mise run build:plugins && mise run verify` before the last commit.

## Review Focus

1. A report filed twice on the same card version: one entry, count 2, the operator's toggle kept. → Task 2, test "the same report twice".
2. A card reworded after feedback was filed: the entry leaves Open (stale) without anyone acting. → Task 2, test "a changed card makes its feedback stale".
3. A malformed or foreign file in `.zarg/feedback/`: skipped, the view still fills. → Task 2, test "a broken entry file is skipped".
4. Space on a table that is not a toggle table keeps ticking rows as before. → Task 1, test "space on a selectable table still ticks".
5. Rehearse finishing with the backlog plugin absent: rehearse is not loaded (it depends on backlog), and says why on the agenda. → covered by the host's existing dependency handling; Task 3 declares the dependency.

### Task 2: `@zarg/plugin-backlog`: the feedback store, its entities and the Feedback view

**Files:** Create `packages/plugin-backlog/{package.json,mise.toml,tsconfig.json}`, `src/contract.ts`, `src/feedback.ts` (pure: ids, upsert, states, rows), `src/views.ts`, `src/index.ts`; tests `test/feedback.test.ts` (pure), `test/plugin.test.ts` (through the host, with gherkin). Modify `packages/plugin/scripts/build-plugins.ts` (`FIRST_PARTY` gains `plugin-backlog`).

**Produces:**
- Contract `Backlog = pluginContract("backlog", { file: { params: { entries: FiledEntry[] }, success: { ids: string[] } }, status: { params: { ids: string[] }, success: { id, state }[] } })` where `FiledEntry = { ref (with version), journeys: string[], persona, kind, severity: "high"|"medium"|"low", note, from: { agent, run }, triage: { on, why } }`.
- `Entry = FiledEntry & { id, count, triage: { on, why, by }, state?: "planned"|"closed" }`; `entryId(e)`, `upsert(existing | undefined, filed) → Entry` (count+1, operator triage kept, agent triage replaced), `stateOf(entry, changed: boolean) → "open"|"stale"|"planned"|"closed"`.
- Entities: kind `feedback` (tone `attention`, glyph `◇`, open `feedback`), ops get, label, version, query.
- Nav `{ kind: "nav", name: "feedback", view: "feedback", label: "Feedback" }`.
- View `feedback`: `stage` (text, summary, title ""): the stepper `● Triage ─── ○ Refine ─── ○ Re-rehearse ─── ○ Plan` and the journey's name; `journeys` (table, primary, title ""): journey, open, stage; default action `journey` (Enter); `feedback` (table, pinned, title "", `toggle: true`, `search: true`): card (`ref: true`), severity (severity tones), kind, feedback, why; `detail` (text, pinned, title "", follows and beside `feedback`): the entry in full and the card as the tester saw it (its `context`).
- `act`: `open` (fill the view), `journey` (rows [journey name] → show its feedback), `toggle` (rows [entry id] → flip, `by: "operator"`, save, refresh).
- Scopes: `fs: { read: [".zarg/feedback/**"], write: [".zarg/feedback/**"] }`, `entities: { read: ["gherkin/*"] }`, `agents: true`.

- [ ] Tests (pure): id is stable for the same ref/kind/note and differs across versions; the same report twice → one entry, count 2, an operator's `on: false` kept; the agent's triage replaced when the operator never flipped it; `stateOf` open/stale/planned/closed.
- [ ] Tests (host, gherkin + backlog built from source): `file` twice → one file under `.zarg/feedback/`; `act open` fills journeys with the entry's journey and its open count; `act toggle` flips and marks `by: operator`; after `gherkin/edit-state` rewords a state the card uses, `act open` shows no open feedback for it (stale); a file with `{}` in `.zarg/feedback/` is skipped; `Entities.get("backlog/feedback:<id>")` returns the entry with its label.
