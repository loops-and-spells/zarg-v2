# Catalog (e2e plan 2 of 4): A Static Site of Intent, Journeys, Scenarios and Their Evidence — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `zarg catalog build [--out site]` writes a plain static site: an overview of the audit, a page per intent, journey and scenario, and search. A human reader can see whether everything works, with each scenario's evidence replayable: casts in the asciinema player, buffers as terminal frames, images, gifs, videos and logs. `mise run catalog` builds it and serves it at `http://localhost:4173`.

**Architecture:**
- **`@zarg/catalog`** is a library with three layers:
  - `model.ts` (pure): it turns the graph, the full audit report and the evidence into page data;
  - `pages.ts` (pure): it turns that data into HTML strings;
  - `build.ts` (fs): it writes the pages and copies media and the player.
- **The CLI** gathers the report exactly as `zarg audit` does (one shared `fullReport` effect), because only a plugin host has the lints and the agenda.
- **Journey flow order** moves out of the gherkin plugin into `@zarg/audit/flow`, so the catalog and gherkin's Journeys view walk journeys the same way. Packages may not import plugin code.

**Tech Stack:** Bun 1.4, Effect 4, `asciinema-player` 3.17.0 (its `dist/bundle` UMD and CSS, copied into the site), `@zarg/tokens` (status colours from the web palettes), `@zarg/highlight` (Gherkin colouring), bun test.

**Spec:** `docs/superpowers/specs/2026-10-04-e2e-suite-design.md` ("The catalog").

## Global Constraints

- `mise run build:plugins && mise run verify` passes before every commit. Commit messages end with `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.
- **Status words** are the audit's own: `proven`, `failing`, `stale`, `unproven`, `planned`. Each has one CSS class `s-<status>` and the same colour everywhere: proven `ok`, failing `error`, stale `attention`, unproven `dim`, planned `faint`. Colours come from `@zarg/tokens` `PALETTES["web.light"]` and `["web.dark"]`.
- **Nothing from a CDN.** The player JS and CSS are copied from `node_modules/asciinema-player/dist/bundle/`.
- **Only committed things go in.** The site holds the graph, `.zarg/evidence/*.json` and its media. A media path that resolves (symlinks followed) outside `<root>/.zarg/evidence/media` fails the build.
- **Deterministic:** the same inputs give the same bytes. Everything is sorted, with no build time in any page. The only times shown are the evidence's own `at`.
- **Any sub-path:** every link is relative (`../journeys/J-0005.html`), with no leading `/`.
- **The operator's words:** pages say "the operator", never "the developer" (persona names come from the graph).

## Review Focus

1. **Graph text with `<`, `&`, `"` or `</script>`** (a scenario title, a state, a buffer frame with ANSI leftovers). Expected: shown literally, never as markup. Task 3 tests it.
2. **A media path that escapes the evidence dir** (`../../.env.local`, or a symlink in media pointing out). Expected: the build fails naming the file, and nothing is copied. Task 4 tests it.
3. **Binary media listed but not committed** (gitignored png). Expected: "captured on the run's machine, not committed", never a broken `<img>`. Task 2 tests it.
4. **A journey whose scenarios loop** (A → B → A), or a scenario in no journey. Expected: the loop shows "↺ back to" and every scenario still gets a page. Tasks 1 and 2 test it.
5. **Building twice into an existing `site/` with stale pages** (a scenario removed since). Expected: the old page is gone, because the out dir is rebuilt from empty. The output must be a directory the build owns, so a `site` that is not a catalog (it has no `.zarg-catalog` marker) is refused. Task 4 tests it.

- Consumes:

- Produces:
```ts
export type Status = "proven" | "failing" | "stale" | "unproven" | "planned"
export const STATUSES: ReadonlyArray<Status> = ["failing", "stale", "unproven", "proven", "planned"]   // red first
export type Counts = Readonly<Record<Status, number>>
export type Line = { readonly keyword: "Given" | "And" | "When" | "Then"; readonly text: string; readonly ref?: string }
export type MediaView = { readonly kind: Evidence["media"][number]["kind"]; readonly caption: string; readonly path: string; readonly present: boolean; readonly text?: string }
export type ScenarioPage = {
  readonly id: string; readonly title: string; readonly status: Status; readonly version: string
  readonly by: ReadonlyArray<{ readonly id: string; readonly name: string }>
  readonly journeys: ReadonlyArray<{ readonly id: string; readonly name: string }>
  readonly lines: ReadonlyArray<Line>
  readonly code: ReadonlyArray<{ readonly file: string; readonly line: number; readonly url?: string }>
  readonly proof?: { readonly run: string; readonly commit: string; readonly at: string; readonly ms: number; readonly flaky: boolean; readonly failure: Evidence["failure"]; readonly media: ReadonlyArray<MediaView> }
}
export type JourneyPage = { readonly id: string; readonly name: string; readonly outcomes: ReadonlyArray<{ readonly id: string; readonly text: string }>; readonly steps: ReturnType<typeof flowOf>["steps"]; readonly apart: ReadonlyArray<string>; readonly counts: Counts }
export type IntentPage = {
  readonly id: string; readonly title: string; readonly status: string; readonly problem: string
  readonly outcomes: ReadonlyArray<{ readonly id: string; readonly text: string; readonly journeys: ReadonlyArray<string> }>
  readonly constraints: ReadonlyArray<{ readonly id: string; readonly text: string; readonly bounds: ReadonlyArray<string> }>
  readonly questions: ReadonlyArray<{ readonly id: string; readonly text: string; readonly answer?: string }>
}
export type Overview = { readonly checks: ReadonlyArray<{ readonly name: string; readonly level: "problem" | "warning"; readonly count: number }>; readonly journeys: ReadonlyArray<{ readonly id: string; readonly name: string; readonly counts: Counts }>; readonly totals: Counts; readonly runs: ReadonlyArray<string>; readonly commits: ReadonlyArray<string> }
export type SearchEntry = { readonly id: string; readonly kind: "intent" | "outcome" | "journey" | "scenario"; readonly text: string; readonly url: string }
export type Catalog = { readonly overview: Overview; readonly intents: ReadonlyArray<IntentPage>; readonly journeys: ReadonlyArray<JourneyPage>; readonly scenarios: ReadonlyArray<ScenarioPage>; readonly search: ReadonlyArray<SearchEntry> }
/** github: links code to `https://github.com/<repo>/blob/<ref>/<file>#L<line>`. readText reads a text medium (relative to the evidence dir); present says whether a medium's file exists. */
export const catalogOf: (input: {
  readonly snap: Snapshot.Snapshot; readonly report: Full
  readonly github?: { readonly repo: string; readonly ref: string }
  readonly readText: (path: string) => string | undefined
}) => Catalog
/** `git@github.com:o/r.git` or `https://github.com/o/r(.git)` → `o/r`; anything else → undefined. */
export const githubRepo: (remote: string) => string | undefined
```
- **Rules:**
  - A scenario's status is its `ProofRow.proof`.
  - Lines are the arrives edge first (Given), the given edges (And), the When, then the then edges (Then, And). Each line's `ref` is the state id.
  - `code` comes from `report.scenarios[].tags`, sorted by file then line.
  - Media:
    - a medium is `present` when `readText(path) !== undefined` for text kinds (`buffer`, `log`, `cast`), and through the same reader for binary kinds;
    - `text` is filled for `buffer` and `log`, never for `cast` (the player fetches it) or binary kinds;
    - media paths keep the evidence's own `media/<S>/<file>`.
  - `overview.runs` and `overview.commits` are the distinct evidence runs and commits, sorted.
  - Search holds every intent (title), outcome (text), journey (name) and scenario (title), sorted by id. The urls are `intents/<id>.html`, `intents/<intent>.html#<O-id>`, `journeys/<id>.html` and `scenarios/<id>.html`.
  - Everything is sorted by id.

### Task 3: Pages

**Files:**
- Create: `packages/catalog/src/pages.ts`
- Test: `packages/catalog/test/pages.test.ts`

**Interfaces:**
- Consumes the `Catalog` types (Task 2), `highlight` (`@zarg/highlight`), and `makeTheme` and `PALETTES` (`@zarg/tokens`).
- Produces:
```ts
export const esc: (s: string) => string                       // & < > " '
export const css: () => string                                  // tokens as CSS vars, light on :root, dark under prefers-color-scheme and [data-theme]
/** Every page as path → HTML: index.html, search.html, search.json, intents/<id>.html, journeys/<id>.html, scenarios/<id>.html. */
export const pages: (c: Catalog) => ReadonlyMap<string, string>
```
- **Layout:**
  - `<!doctype html>`, `<meta charset="utf-8">`, the viewport meta, `<title>{page} · zarg catalog</title>`;
  - `<link rel="stylesheet" href="{up}catalog.css">`, where `{up}` is `""` at the top and `"../"` one level down;
  - a header nav linking Overview, each intent, Search;
  - `<main>`.
- **Pages:**
  - **Overview:**
    - checks in a table, problems first;
    - per journey a bar of `<span class="s-<status>" style="flex:<n>">` segments, in `STATUSES` order, zero ones left out;
    - the runs and commits.
  - **Intent:**
    - the problem;
    - outcomes with `id="<O-id>"` anchors and their journeys linked, or `◇ no journey`;
    - constraints with what they bound linked;
    - questions marked open or answered.
  - **Journey:**
    - outcomes;
    - each step as a `<section>` holding the scenario's Gherkin (highlighted spans `class="t-<token>"`) and a status badge;
    - `→`, `→ … (branches)` and `↺ back to` links;
    - then the "Not connected" ones.
  - **Scenario:**
    - its Gherkin;
    - version;
    - code links (`<a href=url>`, or plain `file:line`);
    - proof (run, commit, at, ms, flaky);
    - each medium:
      - `buffer` → `<figure><pre class="frame">text</pre><figcaption>`;
      - `cast` → `<div class="cast" data-cast="{up}{path}"></div>` with a `<noscript>` link;
      - `image` and `gif` → `<img src alt=caption>`;
      - `video` → `<video controls src>`;
      - `log` → `<details><summary>caption</summary><pre>`;
      - not present → `<p class="absent">captured on the run's machine, not committed</p>`;
    - on failure, `expected` and `saw` (in a frame) first.
  - **Search:** an `<input>` plus a list. The inline script fetches `search.json` and filters by case-insensitive substring over id and text.
  - **The player:** pages with casts load `{up}player/asciinema-player.css` and `.min.js`, then `document.querySelectorAll("[data-cast]").forEach((el) => AsciinemaPlayer.create(el.dataset.cast, el, { fit: "width" }))`.
