# Backlog Implementation Plan (plan 2 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plans live on a Backlog kanban (option D): lanes Backlog, Ready, Running, Review, Done, each its own scroll container that folds to a vertical strip; the Planner Agent applies a Ready plan's drafted card changes to the graph, and the reconcile loop implements them.

**Architecture:** The view SDK gains a `board` section kind (lanes of cards; the view UI keeps each board's lane, card and folded lanes) that `@zarg/view-tui` draws as option D. `@zarg/plugin-backlog` stores items (`backlog/item` entities, `.zarg/backlog/<B-NN>.json`, committed), fills a Backlog nav view with the board and an item sheet (the drawer) with its actions, and moves items on the operator's keys or commands. The core's Planner takes the oldest Ready item (its `after` items done), applies its gherkin tool calls through the host's write pipeline, commits exactly those nodes (`commitGraph`), marks it Running and notifies reconcile; a landed pass moves it to Review (with reconcile off, the apply itself does, saying so).

**Tech Stack:** Bun, Effect 4, the plugin SDK, OpenTUI React, `@zarg/reconcile` (`commitGraph`).

**Spec:** `docs/superpowers/specs/2026-09-28-feedback-backlog-design.md` (The Backlog), mockups option D (`packages/view-tui/mockups/feedback.tsx`, `BoardD`).

## Global Constraints

- Items are plans: `{ id: "B-NN", title, journey, cards: [{ ref, to? }], changes: [{ tool, params }], feedback: [ids], steps: [text], status, agent?, after?: [ids], events: [{ what, by }] }`; one committed JSON file each under `.zarg/backlog/`.
- Lanes: `backlog`, `ready`, `running`, `review`, `done`. A new plan lands in Ready; Backlog holds parked plans.
- No times anywhere on the board or drawer.
- A Ready item whose card changed version since it was drafted shows ⚠ and the Planner does not take it.
- Plugins name only plugin tones.
- `mise run build:plugins && mise run verify` before the last commit.

## Review Focus

1. A lane with more cards than fit: the cursor card stays visible (the lane scrolls), the other lanes do not move.
2. Folding the lane under the cursor: the cursor stays on its strip; ⏎ or → unfolds it.
3. An apply whose tool call fails lint: nothing is committed, the item returns to Ready with the reason as an event, and asks for attention.
4. Two Ready items: the older first; one `after` an item not Done waits.
5. The same item applied twice (a restart mid-apply): the second apply sees the item Running and does nothing.

### Task 4: The Planner applies Ready plans

**Files:** `packages/core/src/planner.ts` (new), `packages/core/src/live.ts` (start it; wake it when a plugin's agenda changes; tell it when a pass lands), `packages/core/src/reconcile.ts` (an `onLanded(cards)` hook). Test `packages/core/test/planner.test.ts`.
- `makePlanner({ invoke, call, exclusive, commit, notify, reconcileOn })`: `tick` asks backlog `next`; applies each change with `call("gherkin/<tool>", params)` under `exclusive`; commits the touched nodes (`commitGraph`, message `req: <title> (<id>)`); `moved` to `running` (agent `Planner`), then `notify()`; with reconcile off, `moved` to `review` with "reconcile is off: implement by hand". A failed call: nothing committed (the graph files restored with `git checkout` of the touched nodes), `moved` back to `ready` with the reason and attention.
- `landed(cards)`: every Running item whose cards all landed moves to Review.
